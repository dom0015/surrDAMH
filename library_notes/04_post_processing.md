## Structure map (Samples class and public functions)

`Samples(no_parameters, samples_dir, decompress_samples=True, load_posterior=False, load_posterior_surrogate=False)`
loads one `StageSamples` per subdirectory of `sampling_output/samples/`, then calls `summarize()`.

| Method | Computes | Depends on decompressed `.samples`? |
|---|---|---|
| `get_mean_and_cov` | weighted mean/cov via `samples_compressed` + `np.average`/`np.cov(fweights=...)` | no (uses compressed+weights) |
| `load_notes` / `load_subchain_stats` / `summarize` | per-stage accept/reject/pre-reject sums, DAMH subchain acceptance/move rates | no |
| `calculate_CpUS` | cost-per-uncorrelated-sample = mean autocorrelation time × ratio of exact evaluations (+ optional surrogate cost) | yes (via `Autocorrelation`) |
| `load_snapshots` / `_load_snapshot_parameters_and_observations` | raw per-snapshot parameters+observations from `raw_data/` | no |
| `plot_chains`, `_plot_hist_1d/2d`, `plot_hist_grid`, `plot_hist_marginals` | trace plots, 1D/2D histograms (weighted via decompression) | yes |
| `hist_observations`, `pdf_report`, `html_report` | 2D histogram of simulated observations vs. reference, legacy PDF/HTML reports (single-file, not "extended") | no (uses `raw_data`) |
| `plot_surrogate_quality[...,_test,_test_weighted]` | reads `surrogate_quality.csv` / `surrogate_quality_test.csv` written by COLLECTOR | no |
| `calculate_effective_sample_size` | ESS = total samples / autocorrelation time, via `Autocorrelation` + `emcee` | yes |
| `plot_autocorr` | per-parameter ACF plot via `Autocorrelation` + `emcee` | yes |
| `plot_acceptance_rates` | bar chart of `accepted/sum` per stage | no |
| `calculate_gelman_rubin` | R-hat over parallel chains (custom implementation, not emcee) | yes |
| `plot_parameter_correlation_heatmap` | Pearson correlation of pooled samples | yes |
| `find_best_fits` | top-`n` best samples from `raw_data` by L2 misfit / log-posterior / log-likelihood (chunked, `argpartition`-based) | no (streams `raw_data` CSVs) |
| `plot_best_fits` | overlays best-fit simulated observation series vs. reference, optional per-sensor faceting | no |
| `compute_posterior_field_statistics` / `plot_posterior_field_statistics` | posterior mean/std of a user-supplied derived field, evaluated per posterior sample | yes |
| `html_report_extended` | single large method assembling the full self-contained HTML report (base64-embedded PNGs) from most of the above | yes (for the "expensive" sections) |
| `Autocorrelation` (separate class) | per-chain ACF via `emcee.autocorr.function_1d`, integrated autocorrelation time via Foreman-Mackey windowing (`autocorr_FM`/`auto_window`, vendored from emcee blog code, not the `emcee` package itself for the "mean" variant) | — |
| `rank_best_fit_candidates` (module-level function) | pure ranking of indices by l2/posterior/likelihood | — |
| `decompress` (module-level function) | expands compressed (weight, value) pairs into a repeated-sample array | — |

`emcee` is imported unconditionally at module top (`post_processing.py:7`) — there is no try/except or optional-dependency fallback. It is a listed `requirements.txt` dependency, so this is a hard requirement, not silently degraded: if `emcee` is missing, **the entire `post_processing` module fails to import**, not just the autocorrelation-dependent methods (`calculate_CpUS`, `calculate_effective_sample_size`, `plot_autocorr`, and everything inside `html_report_extended`'s "expensive sections" that call them).

`core.py:152-195` (`temptemptemp`) is dead code: it has the exact docstring of `html_report_extended`'s old-style signature but the body is just `return` — it is never called (the real call site, `core.py:268`, calls `samples.html_report_extended(...)` directly).

## Suggested improvements
- Fix P2 (`no_unique_samples`) by setting `self.no_unique_samples[i] = len(self.weights[i])` right after `self.weights[i]` is assigned in `StageSamples.__init__`.
- Either wire `rank_best_fit_candidates` into `find_best_fits` (so the tested code path is the one actually used), or drop the tests/function and instead test `find_best_fits`'s real scoring branch directly with synthetic `raw_data` CSVs.
- Vectorize `decompress()` (`post_processing.py:2441-2450`) using `np.repeat(samples_compressed, weights.astype(int), axis=0)` instead of the explicit Python loop — simpler and faster for chains with many unique states.
- Replace the repeated `pd.concat` calls inside `load_notes`/`load_subchain_stats` loops with "accumulate list of DataFrames, single `pd.concat` at the end" — the current pattern is a known pandas anti-pattern (quadratic copies), though impact is small while chain counts stay in the tens.
- Narrow the many bare `except`/`except BaseException` clauses (P6) to `except (KeyError, IndexError, TypeError, AttributeError)` or similar, and log the actual exception message instead of a fixed "NOT AVAILABLE" string, to avoid masking configuration errors as data-availability issues.
- Either honor `chains_to_disp` uniformly across all of `html_report_extended`'s sections, or rename/document the parameter as "chains to restrict for best-fit/observation-histogram sections only" to avoid the false impression of a global filter (P5).
- Remove the unused `torch.mtia` import in `process_SAMPLER.py:12` (P9) — appears accidental.
- Remove the dead `temptemptemp` method in `core.py:152-195` (confirmed unused; only kept as a historical duplicate of `html_report_extended`'s old docstring).
- Add an explicit, user-visible note in the HTML report when `parameters_to_disp` truncates to `min(no_parameters, 10)` (`core.py:234`) — currently a run with >10 parameters is silently reported with only the first 10, with no indication in the report itself that parameters were dropped.
- Consider raising instead of silently down-weighting to `-inf` when `ranking_mode` requires columns the `raw_data` file does not have (P10), so an incompatible/old-format file surfaces a clear error rather than a misleadingly complete-looking best-fit table.

## What should be tested or validated
Concrete, MPI-free pytest ideas for pure/near-pure functions in `post_processing.py`/`modules/tools.py` (none of this requires running the sampler):
- `decompress(samples_compressed, weights)`: synthetic small array, assert shape `(sum(weights), n_parameters)` and that each compressed row appears exactly `weights[i]` consecutive times.
- `StageSamples`/`Samples.get_mean_and_cov`: write tiny synthetic `samples/<stage>/rank0000.csv` files (weight, params, log_posterior) to a temp dir matching the real directory layout, and check the weighted mean/cov against a hand-computed reference (would also catch regressions like P1/P2 automatically if `no_unique_samples` were asserted).
- `find_best_fits` (the actual production ranking code, not just `rank_best_fit_candidates`): synthetic `raw_data/<stage>/rank0000.csv` with known misfits/log-likelihoods/log-priors, across more rows than `n_best` to exercise the chunked `argpartition` merge path (`chunk_size=50000` is currently only reachable with huge files — worth adding a small-`chunk_size` override or monkeypatching it in a test to exercise the merge logic without huge fixtures); assert output matches a naive full-sort baseline for all three `ranking_mode`s, and that `"prerejected"` rows are always excluded.
- `Samples.calculate_gelman_rubin`: feed a few synthetic parallel chains with known within/between variance and check the R-hat formula against a hand/`arviz`-computed reference (or at minimum check R-hat≈1 for chains drawn i.i.d. from the same distribution, and >1 for chains offset in mean).
- `autocorr_FM`/`auto_window` (Foreman-Mackey windowed-tau estimator): feed a known synthetic autocorrelation function (e.g. exponential decay `rho(k)=phi^k`) and check the estimated tau is close to the analytic `(1+phi)/(1-phi)`.
- `_plot_hist_1d`/`_plot_hist_2d` bin-count heuristics: a regression test asserting `no_unique_samples_sum` (and hence auto-selected bin count) scales with actual sample count would have caught P2 immediately.
- `rank_best_fit_candidates` (existing test): keep, but also add a test asserting `find_best_fits` produces the *same order* as `rank_best_fit_candidates` on the same synthetic data, to close the P3 gap and give the orphaned function a purpose (or delete it).
- Manual/integration check (not run in this review): run one of the `toy_examples/post_processing_*.py` scripts end-to-end and diff the produced `summary.csv` column names against `summarize_tsx2_results.py`'s expected field names — would immediately surface P4.
